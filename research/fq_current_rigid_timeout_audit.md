# Missing native output audit

The completed current-rigid sweep has 47 `no_native_output` trials. A read-only check of all 47 original trial records, stdout/stderr/logs, inputs and parent archives found genuine native timeouts at the ten-second cutoff: zero error returns, zero final output files, and exactly zero stdout and stderr bytes in every case. The combined logs contain only the deliberately inserted separator newline. The separate n969 certification TypeError is not one of these missing-native-output trials.

Consequently there is no saved evidence of improved side/energy, optimizer phase or near-completion from which to choose a justified longer-budget subset. The pinned native source writes its final configuration and JSON report only after quench completes; its intermediate diagnostics are conditional on verbose/debug settings absent from these commands. Silence is therefore not evidence that optimization made no progress, nor an infeasibility result. It is simply insufficient evidence to prioritize an unchanged retry, especially after the seven previous no-output retries yielded no wins.

No native, LP or metric work was performed by this audit. No longer-budget subset or rerun is proposed. Exact per-file hashes and records are preserved in `artifacts/fq-current-rigid-timeout-audit-v1/audit.json`, SHA256 `cc851f5c9faf44ccf63a66c89962eec8507e3c4accec6bf078cc317f41821721`. The audit completed within the authorized short read-only scope; campaign/source files remain unchanged.

## Single traced diagnostic supersedes the initial retry decision

The root requested an observational diagnostic before closing the cutoff question. The existing pinned native binary supports `--v`, `FQ_TR=1` and `FQ_LPT=1`; no binary rebuild or numeric parameter change was needed. One representative high-gap timeout, n858/job13, was rerun with the exact original parent/input/seed/rigid settings and a 26-second native ceiling. The first diagnostic command had a syntax error before execution; the corrected command invoked the native solver exactly once.

That run completed successfully in 12.40 seconds. Its native report attributes 2.051 seconds to ALM and roughly ten further seconds to contact polishing. The original ten-second cutoff therefore landed in late polish, between accepted iterations 10 and 13 of the final 16, before coordinates were written. Logged low ALM side values with overlap were not treated as valid packings.

The actual returned geometry passed the existing bounded clearance decode, official raw and ordinary-pandas gates, and both independent interval gates. Its certified side upper bound is 29.788821804720997535048279944670 versus 29.789623508437757748582258101225, a score improvement of 0.0000273697136111. Exact traced source/input/parent/logs and full certificate are frozen under `artifacts/fq-rigid-timeout-trace-n858-v1/`; candidate JSON SHA256 is `83aed2f15bdf24a67f22ccb4670359992f2872e8460bbb230ae9ee64cb2f29de`. This new evidence supports a finite extension test; it does not establish that all 47 silent timeouts were near completion.

The root consequently authorized a separate 16-case, three-worker, 240-second follow-up, with a 30-second native cap and separate six-second certificate cap. Exact unchanged parents and original seeds must be verified against the new fc931 RAW portfolio; n858 is excluded. Only observational logging and cutoff budgets change.
