# Batched smooth ALM feasibility pilot

This is a minimal FP64 implementation of FQ's separating-line augmented Lagrangian, following the native objective at MIT commit `659ee62e4a9d39542a1146e8b011cc3ab6407ede`. It follows the separately validated objective and actual T4 throughput experiment in `fq_torch_objective.md` and `fq_torch_gpu_benchmark.md`. It is an experimental solver; raw optimization states are not valid packing certificates.

`experiments/fq_torch_alm.py` gives each replica independent L-BFGS history, Armijo step, multipliers and penalty. Every square retains all three pose variables. Each replica owns a padded near-pair list. A trial is rejected before evaluation if any center leaves the half-skin displacement bound. At an accepted-state rebuild, surviving sorted pair IDs keep their separating line and multipliers; new pairs receive initialized lines and zero multipliers. Changes to the pair list, radius or ALM objective start a fresh inner history. The exact rounded support returns to radius zero; no soft-aspect model is included.

Five local controls cover heterogeneous row independence, failed-trial state retention, trial-before-evaluation coverage, exact pair-state transport, heterogeneous native objective/gradient agreement, and actual overlap repair. Independent controls in `artifacts/fq-torch-alm-independent-review-v1` additionally compare masked pair counts `[2,0,1]` with penalties `[3,11,71]` to separate scalar evaluations. Core SHA is `c3ce3b8a99f55776bcb4727ad98dd100bad678593746fbdc828436699c03eb83`.

The private pilot `sos54352/squares-fq-torch-alm-prototype/1` uses frozen bundle `artifacts/fq-torch-alm-job-v2`, source SHA `477fcf1001bca71020f16c2668951ec279a39c2176f55b7fa989d893e379059e`. Its 26 exact payload files and 13 arrays were independently reviewed. Before exploration, the actual GPU must pass native and heterogeneous masked objective gates, displacement rejection, actual full-147 pair-overlap repair, complete 147/299/335 rigid-return certificates, and a full-335 last-index duplicate negative control. The exact CPU surrogate of these controls passed in 0.65 seconds; it is explicitly not GPU evidence.

The 32 exploratory replicas use three complete 335-square starts: the canonical 44-tilt layout, a certified 43-tilt removal/filler rearrangement, and a certified 37-tilt buffered construction. They hold each source's own box through radii 0.3, 0.1 and 0, then test fixed compression depths 0.0002, 0.001, 0.01 and 0.02 (eight replicas each), followed by free-side rigid release. These are planned stages; the output records actual completed stages and partial coverage. Exploratory optimization has a 180-second deadline checked between outer solves; the entire worker has a hard 300-second process-group bound, a 475-second parent alarm and a 600-second server cap.

Every completed actual outer state is atomically retained with all poses, sides, pair IDs, masks, lines, multipliers, list references and hashes. At most four rigid-stage candidates receive separate final gates. Exact corrected arrays and their certificates are published immediately after each completed admission. There is no native finishing in this pilot. Named downloads preserve the index, summaries and selected packets without requiring a large output ZIP or a second notebook mount. No competition submission is part of this experiment.

The actual T4 run completed normally in 65.73 seconds, including 50.02 seconds of optimization. All mandatory live controls passed in 1.02 seconds. The injected full-147 pair had signed gap -0.003018 before repair and zero final lifted violation; its exact corrected geometry and complete raw/default-pandas/interval certificate are saved. The 299/335 controls preserved valid full counts through all three radii. All five exploratory stages executed, with outer counts 7/6/7/7/7, and all 47 raw packets retain 1,132 complete poses. Peak allocated GPU memory was 76,500,480 bytes; final per-replica lists used 1,160–1,165 active pairs.

There was no packing improvement. The final release states had physical sides 18.82701876–18.84254621, all worse than the frozen canonical 18.82287566, while still retaining small pair overlaps. The best fixed-compression states had physical side/lifted residual pairs 18.82270331/2.16e-5, 18.82202091/1.09e-4, 18.81435637/0.001122 and 18.80563319/0.002214 for the four depths. These are invalid raw states, not scores. The pilot's four automatic gate attempts selected early-release states by small physical span and rejected all four; that selection does not exhaust the retained states. A separately authorized native finishing experiment can test the four fixed-compression states without treating their spans as admissible.

Named results and receipts are in `artifacts/fq-torch-alm-results-v1`; the final held-rigid/compression/release packets and exact control certificates are in `artifacts/fq-torch-alm-selected-raw-v1`. Their 96 exploratory arrays were hash-checked and exported unchanged to `artifacts/fq-torch-alm-native-handoff-v1/raw_states.npz` (SHA `158997c79816cb1c3b4e47d58d42d818d0de66ae64dd1eef7910eea731512314`), with per-array, source and raw-packet bindings in `analysis.json`. The other completed raw packets remain preserved remotely. The result establishes a functioning batched optimizer and live repair path, but does not establish useful full-size contraction or better packing basins.

The separate native finish of the four compressed states completed in 30.08 seconds. All four became fully certified rigid packings, with sides 18.82287573734, 18.82287569118, 18.82288275422 and 18.82287839792: no strict gain over the incumbent. This removes the overlaps while returning near the existing minima, without the larger GPU release-stage inflation. Exact outputs and input bindings are retained under `artifacts/fq-torch-raw-native-finish-v1`; the four-pose archive SHA is `58974bf8e064c529ae267ea04cb7ef34d26d9a5c3de987fbf2583f299cd116e0`.
