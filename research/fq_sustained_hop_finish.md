# Sustained-campaign finishing helper

`experiments/fq_sustained_hop_finish.py` is a new isolated derivation of the
reviewed cold17f0 helper. It permits only the twelve authorized cases and cuts
0.0005/0.002. The caller must supply an explicit diagnostic-selected
`batch_size` of32,64 or128, matching the exact committed design. Root selected
B64 for the proposed production protocol after the occupancy diagnostic.

The original terminalaab5 function is cloned with one hash/count-guarded text
replacement: its seed expression becomes constant9710000. Every selected
state at both cuts therefore matches the native seed used by its case's
single original control. Numerical flags and all terminal gates are
unchanged. The new manifest records original/generated function hashes and
each case/batch/cut/metadata substitution. Both original helper files remain
unchanged and hash-verified before derivation.

Four exact committed BEST slots use the existing minimum-energy plus
near-best-band coarse D4 diversity rule, with duplicate/zero-distance/fallback
labels and all input/archive/index/design/box bindings preserved. Two native
workers per case retain every valid output, including worse scalar sides;
native/gate caps are sixty/eight seconds. The caller provides an absolute
finish deadline. Four full allocations require two68-second waves plus IO;
the proposed campaign allocates145 seconds per case separately from its
global bootstrap/finalization reserve.

Three local tests pass, including an actual forked pool at each of B32/64/128
with mocked native calls. They verify the constant seed for all four slots,
unchanged flags and60/8 caps, retention of valid worse poses, explicit batch
selection and design matching, and seed-only derivation. No optimizer or GPU
was run. Receipt: `artifacts/fq-sustained-finisher-review-v1/local-controls.json`.
